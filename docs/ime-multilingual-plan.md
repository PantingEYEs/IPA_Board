# IPA Board：候选词栏、多功能栏与多语言混输方案

日期：2026-09-27。更新：2026-10-02。状态：已实现逐词混输及 LatinIME 英文补全、纠错、词库上下文预测；当前交付范围与限制见 `engine-integration.md`。

补充约束：候选词栏和多功能栏属于 IME 固定外壳，位于用户键盘布局上方，不进入应用内布局预览、编辑、导入导出和外观配置。

## 1. 目标与默认约定

在现有 Kotlin / Android 原生 View IME 上增加可展开候选词栏、剪贴板面板、键盘页总览，以及简体中文、繁体中文、英文、日文的离线混合输入。

采用 **Rime + Mozc + LatinIME + 应用侧统一组合输入与排序**。同一串拉丁字母同时参与中文拼音、英文单词、日文罗马字解释；不同语言的有效候选进入同一个列表，用户不必切换语言或键盘页。

本方案默认中文使用全拼，日文使用罗马字；以后可增加注音、双拼、假名键位。简体、繁体是同一中文候选通道的不同书写形式，不作为两个独立语言概率重复计权。

“混输”分两层交付：

- 首版支持在同一键盘连续选词组成多语言句子，例如依次输入、选词得到“今天用 Android，明天去東京。”，过程中不切换语言。
- 后续支持把一整段无分隔的跨语言编码自动切成多个片段并生成整句候选。仅将几个引擎的整串结果放在一起，不能保证完成这项能力。

## 2. 现有项目的接入点

| 现状 | 改造方向 |
| --- | --- |
| `IpaBoardService` 创建输入视图、读取设置并派发按键 | 保留服务入口，新增组合输入协调器与面板状态管理 |
| `KeyboardInputController` 对 TEXT 直接调用 `commitText` | 在调用前增加文本路由；组合输入由新控制器处理，原控制器保留直输与快捷键职责 |
| `KeyboardRenderer.render` 清空整个传入容器并重新生成按键 | 只传入独立的 `keyboardHost`，不允许清空候选词栏和工具栏 |
| `keyboard_view.xml` 只有单个纵向容器 | 改为固定顶部区域、键盘区域与覆盖面板 |
| `LayoutFileManager.listLayoutFiles()` 已可枚举布局 | 首版将每个布局文件视为一个键盘页，复用加载和当前布局设置 |
| 配置版本为 2，旧配置缺少新的文本路由字段 | 新字段使用明确版本迁移，旧布局继续直输 |

继续使用原生 View；本次无需迁移 Compose。项目目前最低 API 35，目标 API 36，应在这两个版本验证编辑器、返回手势和原生库兼容性。

## 3. 界面与面板交互

固定布局如下，展开只覆盖键盘区域，IME 窗口高度不随面板切换变化：

```text
┌──────────────────────────────────────┐
│ 多功能栏： [剪贴板] [键盘页总览]       │
├──────────────────────────────────────┤
│ 编码：shijie                [原样上屏] │
│ 候选：世界  世界〔日〕 …          [⌄] │
├──────────────────────────────────────┤
│ keyboardHost                         │
│ 当前键盘页                           │
│                                      │
│ overlayHost 在此覆盖整个键盘区域：    │
│ 候选全集 / 剪贴板 / 键盘页总览        │
└──────────────────────────────────────┘
```

图中文字仅表示结构，不承诺示例编码的真实候选或顺序；完全相同且替换范围相同的文字在实际列表中合并显示。

建议工具栏 40–48dp、候选区约 64–72dp（编码行加候选行），实际数值经真机调整。原有 `heightDp` 继续表示按键区域高度，以免升级后按键变小；总高度为按键高度加顶部区域与适用的系统 inset。横屏或窗口空间不足时压缩按键区并限制总占用高度。

**候选词栏**

- 折叠时横向滚动，右侧展开按钮固定；每个候选可带轻量的“简 / 繁 / EN / 日”标记，标签不参与上屏。
- 展开时用可回收列表展示候选，支持变宽词块换行、长词换行及分页；收起按钮始终可见。
- 点击候选后提交对应文本；首版完整候选提交后收起面板；将来部分候选提交后保留剩余组合输入。
- 空输入可显示英文下一词预测；没有候选时显示空闲提示。组合词候选替换当前组合文本，预测只向游标插入文字。仍保留原样提交入口。

**面板状态**

使用单个互斥枚举 `KEYBOARD / CANDIDATES / CLIPBOARD / PAGE_OVERVIEW`。工具按钮可直接切换面板，再点当前工具按钮返回键盘。展开面板禁止底层键盘接收触摸及无障碍焦点；返回操作先关闭面板，再由系统处理隐藏 IME。仅在面板打开期间拦截对应返回行为，并测试 API 35/36 的返回手势。

**键盘页总览**

- 网格展示布局名称、缩略图和当前页标记；缩略图可复用 Renderer 的只读渲染，不提供按键输入。
- 点击后更新 `KEY_ACTIVE_LAYOUT_FILE`、渲染选中页并关闭总览，不跳转设置 Activity。
- 切页保留组合文本、候选与语言偏好，只重置 Shift/Ctrl。现有设置监听器的布局重置逻辑需要拆分，不能连带清空组合状态。
- 布局被删除或损坏时提示并回退可用页，组合文本保持；列表和缩略图后台加载并缓存。

## 4. 引擎与词库选型

| 通道 | 建议组件 | 职责及边界 |
| --- | --- | --- |
| 中文 | librime + 全拼方案，原型可使用朙月拼音 | 拼音解析、词语/句子候选、用户词学习 |
| 简繁变体 | Rime 原生繁体候选 + OpenCC | 为中文候选生成简体形式，同时保留繁体；不转换英文、日文或整段已提交文本 |
| 英文 | LatinIME 核心，固定 HeliBoard 4.1 来源与 en_US v54 词库 | 单词补全、编辑距离纠错、词库 bigram 下一词预测；个人学习后续实现 |
| 日文 | Mozc 核心 + JNI 适配 | 罗马字到假名、日文转换、日文候选 |
| 融合 | Kotlin `CandidateRanker` | 跨通道排序、去重、偏好与交互稳定性 |

这是三个原生引擎、三个逻辑候选通道，避免为简繁各启动完整引擎。Rime 只处理中文，英文的 easy_en session 和资源已移除；由应用统一决定空格与提交行为。

Rime 明确支持繁体及通过 OpenCC 转换简体；OpenCC 是转换库，不能替代输入法引擎。繁体首版使用一种明确的标准形式，台湾、香港地区词汇可后续作为偏好配置，不能把机械简繁转换等同于地区词汇预测。[Rime](https://github.com/rime/librime)、[OpenCC](https://github.com/BYVoid/OpenCC)、[朙月拼音](https://github.com/rime/rime-luna-pinyin)。

Mozc 项目面向多平台，包括 Android，但不能据此假设当前主线可直接作为 Android SDK 接入；必须先完成固定版本的 NDK 构建、数据打包、会话调用验证。也不等同于获得 Google 日语输入法的全部词库与产品能力。[Mozc](https://github.com/google/mozc)。

依赖锁定 commit、补丁与词库版本。实际打包的 Trime 与 HeliBoard 发布库包含 GPL 声明，不能只按其基础库许可证理解；Mozc、词库和第三方声明分别保存。具体来源、许可材料和限制见 `engine-integration.md` 与资源锁文件。

## 5. 统一输入管线

```text
KeySlot
  → KeyEventRouter
    → 直输 / 快捷键 → 现有 KeyboardInputController
    → 组合字符 → CompositionController
                    ├─ Rime 中文 session → 简繁候选生成
                    ├─ LatinIME 英文（附游标前短上下文，允许空编码预测）
                    └─ Mozc session
                  → CandidateRanker → CandidateStore → 候选 UI
候选点击 → CompositionController → InputConnection → 引擎同步/学习
```

只有 `CompositionController` 能把组合输入写入当前 `InputConnection`。引擎自身返回的提交结果必须先转成数据，不允许任意一个引擎自行向宿主上屏。输入一次按键只形成一次可追踪的状态变更。

新增键位字段 `textBehavior = literal | compose | auto`：旧版键位迁移为 `literal`；新增通用 QWERTY 页使用 `auto`，ASCII 字母及合适位置的撇号进入组合，其他文本按边界规则直输；明确的 `compose` 键可提交一批受支持编码。IPA、多字符短语、符号保持直输。键盘页不选择语言，一个 QWERTY 页即可完成四种文字输入。

保留用户原有页面，并新增可用的通用 QWERTY 页，因为当前项目默认键位为空，仅添加引擎并不能让用户直接拼音/罗马字输入。

组合状态至少包含 `editorSessionId`、单调递增 `revision`、原始编码、编码光标、上下文摘要和当前候选快照。首版仅允许在编码末尾编辑；移动宿主光标前按原样结束组合，不假装支持任意位置重转换。

**关键按键语义**

| 操作 | 有组合文本时 | 无组合文本时 |
| --- | --- | --- |
| 普通编码键 | 更新原串，刷新组合显示和候选 | 启动组合 |
| 退格 | 删除一个输入单元并重新查询；删空清理 composing | 保留现有选区/Unicode 删除行为 |
| 点击候选 | 提交该候选，清除已消费原串 | 提交显式联想候选（若以后实现） |
| 空格 | 选当前快照首选；英文或原文追加一个空格，中文/日文不追加 | 插入空格 |
| Enter | 原样提交当前编码并结束组合，本次不发送/搜索 | 保留现有 editor action 行为 |
| 原样上屏 | 按用户输入的大小写提交，不纠错 | 无操作 |
| 标点、IPA、literal 短语、粘贴 | 先原样结束组合，再提交对应内容 | 直接提交 |
| 方向键、Home/End、Ctrl 快捷键、Tab | 原样结束组合，再执行原有动作 | 原有动作 |
| 切键盘页、开关面板 | 保留组合 | 仅切换 UI |

每次用 `setComposingText` 展示统一原串，不能因某个引擎暂时领先就把拼音改成假名。宿主不可靠支持 composing 时使用栏内组合显示，选词后一次提交。`setComposingText` 返回成功只说明请求被发送，仍需兼容实际编辑器。[Android IME 指南](https://developer.android.com/develop/ui/views/touch-and-input/creating-input-method)、[InputConnection](https://developer.android.com/reference/android/view/inputmethod/InputConnection)。

实现 `onUpdateSelection`，区分自身写入产生的预期回调与外部选区移动；外部移动时结束旧组合标记、清理状态，不向新光标位置重提旧串。切换编辑器立即增加 session 标识并丢弃旧结果；结束输入时只结束已有 composing 标记，不自动选择候选、不向新连接写入。只读或失效连接不产生学习记录。

## 6. 多引擎查询与一致性

适配器提供 `query(snapshot)`、`select(candidateRef)`、`reset()`、`close()`；实际原生接口由适配器转换，不把原生内部状态暴露给 UI。

各查询携带 `(editorSessionId, revision, engineGeneration)`。每个引擎使用串行执行器；Rime 多 session 的调用先统一串行，验证线程安全前不在多个线程同时调用同一个 runtime。Rime 与 Mozc 可并行运行，主线程只处理输入状态和视图。

快速打字合并尚未开始的旧查询；对已运行的原生调用，即使无法真正取消，也丢弃过期返回。快照查询可以用重置和重放原串实现首版正确性，再优化增量输入。查询、重放、分页不得触发虚假用户学习。

候选点击必须使用稳定 ID 和原生候选引用，不以列表下标提交。下指时冻结命中项，抬指按该 ID 处理；引擎状态已过期则重新查询，不提交错误候选。慢引擎稍后返回可以增补列表，但不能把用户手指下的词换掉。

提交后只对被选中的来源学习，其他 session 重置/同步剩余编码。简体变体保留其繁体源候选引用，学习源词并单独记录书写偏好。引擎无法无副作用地通知学习时，首版先使用应用层选择计数，不能为“学习”重复提交或重复喂按键。

原生崩溃不能依赖 Kotlin `try/catch` 隔离；发布版本建议将两类原生引擎放入独立的私有服务进程，通过 Binder 交换小批候选。正常异常与超时先降级；进程死亡后禁用对应通道、受限重启，保留原串和其他通道候选。原型允许同进程验证，但不得宣称具备崩溃隔离。

## 7. 候选模型与跨语言排序

候选结构建议包含：

```text
stableId, editorSessionId, revision
displayText, commitText, language, script
sourceRefs[] = (engine, sessionGeneration, nativeCandidateId, rank)
consumedRawRange, remainingRaw, matchKind
nativeScore? , mergedScore, variantGroupId?
```

统一规定原串范围使用 Unicode code point 索引，在适配器边界转换 Rime/Mozc 原生偏移；Android 文本位置再转换为 UTF-16。不能混用字节、假名字符、原串字母和 UTF-16 索引。

**不直接比较原始分数。** Rime C API 的基础候选结构提供文本和注释，并未提供跨引擎可比的概率；Mozc 排序、代价也不与 Rime 同尺度。因此 `nativeScore` 可空，第一版主要使用来源内排名及共同特征。[Rime API](https://github.com/rime/librime/blob/master/src/rime_api.h)、[Mozc 协议](https://github.com/google/mozc/blob/master/src/protocol/commands.proto)。

初期用可解释的启发式分数，所有特征归一到 0–1，权重通过开发语料调整：

```text
S(c) = w1·来源内排名特征 + w2·输入匹配质量
     + w3·上下文适配度   + w4·本机历史选择偏好
     + w5·简繁书写偏好   − w6·补全/纠错惩罚
```

来源内排名可以使用 `1 / (k + rank)`，再按固定规则归一化；不同引擎采用各自偏置，不能因为每家都有第一名便认为概率相同。完全匹配通常优先于长前缀补全；短而歧义大的编码降低语言偏置，近期选过日文也不能彻底排除中文、英文。

排序流程：

1. 各通道先取有界数量，如前 20 项，原始编码始终可原样提交。
2. 为中文源候选生成简繁变体；两者共享源词证据，不将转换结果当成第二次独立支持。
3. 按“实际提交文本 + 消费范围 + 剩余原串”精确去重，保留全部来源。简繁不同字形保留；中日同形词且提交效果一致可合并多语言标签。避免 NFKC 等会改变字符语义的激进去重。
4. 用统一分数排序，稳定 ID 用于增量更新；首版只开放覆盖完整原串的候选，防止误删未消费输入。
5. 同一中文词的多个变体不要挤满首屏。按变体组做轻量去重拥挤控制，低置信度时允许有效的其他通道候选进入前列；这属于展示多样性规则，不声称严格概率降序。
6. 展开后按需向各通道取下一页并重新融合，不一次加载整部词典；未加载结果不能宣称已参与全局排序。

后续收集经许可的开发/评测数据和可清除的本机选择记录，训练轻量线性/树模型，估计候选被选择的可能性。若使用语言混合模型，可按 `P(语言|编码,上下文) × P(候选|语言,编码,上下文)` 建模，并在统一候选集合上校准。不能把多个各自 softmax 的值直接拼成“真实概率”。没有跨语言标注集之前，产品只展示排序，不显示概率百分比。

简繁选择属于书写偏好，默认近似中性，随后按选择调整；原词的总概率质量需要在变体之间分配，避免一词两种写法使中文通道权重翻倍。

## 8. 连续跨语言整串输入的后续扩展

对 `woainihello` 这类无分隔原串，增加跨语言分词层：枚举有限长度的原串片段，向各通道取候选，以消费区间为边构建图，用有界 beam search 选取覆盖完整原串的路径。路径分数考虑片段候选、跨片段上下文和语言切换代价，避免过度切成单字母。

接口从第一版保留 `consumedRawRange`，但完整功能应单独验收：日文转换片段必须映射回罗马字消费范围；选择部分片段后提交前缀、重建剩余 composing 并同步各 session。成本、延迟及准确率未经验证前，不把它列入首版已支持能力。

## 9. 剪贴板

首版面板展示系统当前文本剪贴板，点击粘贴；空内容、非文本内容、读取失败有明确提示。默认不在后台采集历史，也不把剪贴板内容送入引擎学习。打开面板时刷新当前内容，不把 `ClipboardManager` 当成可查询系统历史的 API。

Android 10 起限制非前台、非默认 IME 的剪贴板读取；本应用作为当前默认 IME 使用标准接口，仍处理系统返回空值或访问被拒绝。敏感剪贴项隐藏预览，允许用户明确点击粘贴，不保存到历史。[Android 剪贴板访问限制](https://developer.android.com/about/versions/10/privacy/changes#clipboard-data)、[复制粘贴指南](https://developer.android.com/develop/ui/views/touch-and-input/copy-paste)。

可选历史功能后续再做：用户启用后记录本应用可观察到的条目，最多 20 条、默认 24 小时过期，支持删除与清空；不承诺恢复安装前或服务未运行时的历史。若持久化，限制大小、排除备份并加密保存。

密码字段使用直输，禁止记录上下文、引擎学习和剪贴板历史；`IME_FLAG_NO_PERSONALIZED_LEARNING` 等编辑器偏好应传播到所有引擎。隐私模式仍可用静态词典，但不能暗中写入用户词库。

```text
  固定版本的构建配置、JNI、词库清单及许可证材料
```

配置升级到 version 3，增加键位 `textBehavior` 和可选 IME 偏好；旧配置缺失字段默认 literal。未知枚举仍拒绝导入。用户词库、输入历史与剪贴板不进入布局 JSON；引擎资源版本由资源清单管理，不能由导入布局任意指定可执行插件。

原生引擎与词典在后台初始化/部署，资源预编译与设备架构适配需验证。首先支持 arm64-v8a，模拟器使用 x86_64；验证 16KB page size 设备兼容。部署期间界面显示状态并允许原文提交；资源升级使用临时目录与原子切换，保留可回退版本。

## 11. 分阶段实施与验收

| 阶段 | 工作 | 完成条件 |
| --- | --- | --- |
| P0 原生可行性验证 | 固定 Rime/Mozc 版本、NDK 构建、词库部署、session、查询/选择/重置、许可材料 | arm64 真机和 x86_64 模拟器能稳定取得真实候选，测出启动耗时、内存、包体；Mozc 构建失败须解决或重新选型，不能用假候选冒充 |
| P1 UI 框架 | 容器拆分、候选折叠/展开、工具栏、当前剪贴板、键盘总览 | 面板等高覆盖键盘，触摸不穿透，切页生效且原有输入回归通过 |
| P2 组合输入 | 路由字段、QWERTY 页、组合控制器、生命周期 | 原串、退格、原样提交、快捷键、选区变化行为符合表格，无丢字/重复上屏 |
| P3 四种文字混输 | 三通道、简繁变体、混排、稳定 ID、分页与失败降级 | 同一键盘可连续输入四种文字；有有效候选的通道参与统一排序 |
| P4 排序调优与发布验证 | 评测集、上下文/偏好、性能、进程恢复、编辑器兼容 | 达到约定的质量和性能门槛，保留离线与数据清除能力 |
| P5 整串跨语言解析 | 区间候选、beam search、部分提交 | 独立通过连续跨语言输入准确率与延迟验收 |

P0 必须先于引擎规模接入，P1 可先使用明确标记的测试数据验证 UI。P0 后再估算工期，当前不把未经实测的包体、内存和构建难度当作已知值。

建议性能目标（待 P0 在指定中端设备验证）：暖启动后首批候选 P95 ≤ 80ms，完整首轮融合 P95 ≤ 150ms，键盘 UI 不等待引擎；超过预算先展示已就绪通道。记录冷启动、内存峰值、CPU、电耗及各 ABI 包体，不通过无限预加载换取延迟。

验收应覆盖：

- `nihao`、`shijie` 的中文候选；`hanshu` 等可产生不同简繁字形的编码；英文词与前缀；`konnichiha`、`nihongo` 日文转换，以及 `shi`、`no` 等跨语言歧义。具体排名通过实测基线确定，不硬编码假定顺序。
- 用同一 QWERTY 页组成“你好／你好、漢語／汉语、hello、日本語”等混合内容；证明无需切换语言。
- 快速连输/连删、旧结果迟到、候选刷新时点击、分页后点击、引擎退出重启，均不提交过期候选。
- 展开/收起、剪贴板与总览互切、旋转、横屏、返回手势、TalkBack、大字体，面板均不穿透键盘。
- 普通 EditText、浏览器/WebView、聊天编辑器、搜索框、密码框：组合替换、Enter、选区变化、切应用均不丢字或重复提交。
- 原有 IPA 组合字符、多字符键、Ctrl、Shift、退格、布局导入导出继续工作。
- 排序评估采用分语言与混合语料的 Top-1、Top-5、平均选词位置、修正次数及延迟；单独看简繁选择，避免总体均值掩盖少数语言退化。

先运行项目现有单元测试、构建与 lint，再增加组合状态、异步版本隔离、排序去重和配置迁移的针对性测试；原生适配器用真实引擎集成测试，面板与跨编辑器行为使用仪器测试和真机检查。

## 12. 方案结论

推荐先交付可用的候选栏和工具面板，再用统一组合状态接入 Rime/Mozc。首版完成四种文字无需切换的逐词混输，候选使用明确的启发式统一排序；后续以跨语言数据校准“可能性”，再扩展整串自动分词。工程上的优先级是提交正确、原有 IPA 输入兼容、候选来源可追踪，其次才是复杂预测。
