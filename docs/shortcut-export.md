# Shortcut 配置导出

在 **Shortcut Management → Export configuration** 选择文件保存位置。默认文件名为 `ipa_board_shortcuts.json`，成功后页面显示 **Shortcut configuration exported.**；取消和失败分别提示，不修改已保存配置，也不执行任何绑定。

文件包含目标确认时已保存的 Shift／Ctrl 映射、六个多功能栏位置的绑定，以及已实现的 Replacement Text 规则。对话框中尚未保存的编辑不包含在内。本阶段仅提供导出，不提供导入、冲突合并或部分恢复。

## 格式 v1

使用 UTF-8 JSON，顶层 `format` 为 `ipa-board-shortcuts`，`schemaVersion` 为整数 `1`，`categories` 按类别组织：

| 类别 | 内容 |
| --- | --- |
| `shift` | 按键字符串到稳定功能标识的对象；空映射为 `{}` |
| `ctrl` | 按键字符串到稳定功能标识的对象；空映射为 `{}` |
| `multifunctionBar` | 按稳定位置标识保存绑定；每个已知位置包含 `action`、完整 `text`、`textBehavior` |
| `replacementText` | 保留已有类别的 `schemaVersion: 1`、`category: "replacementText"` 及有序 `rules` 数组；没有规则时为 `[]` |

六个位置为 `left_first`、`left_second`、`left_third`、`right_first`、`right_second`、`right_third`，与页面显示标签无关。未保存的位置使用当前默认绑定，缺少 Shift／Ctrl 配置表示空映射。缺少替代文字配置会生成合法的空规则类别。

文字不使用界面预览的截断值，也不做去空白、大小写或宽度转换。换行、引号、反斜线、Emoji 和 IPA 字符均保留；UTF-16 代理项采用 JSON 转义，以免写成 UTF-8 时丢失孤立代理项。替代规则保留 ID、顺序、重复源文字和重复目标，不按源文字合并。

已保存的未知动作标识和附加 JSON 字段保留原值。类别类型或结构损坏、替代规则 ID 重复、无法识别的替代规则格式版本都会使导出失败，不用空值或默认值冒充完整导出，也不自动修复原配置。未来增加类别时须明确格式兼容语义，不能把缺少类别的旧文件视为已经包含该类别。

## 保存与边界

使用系统文件选择器创建用户指定的文档。打开选择器前检查配置可读取，选择目标后重新读取一个完整设置快照再写入；返回页面或重建活动不会执行绑定。全部写入、刷新和关闭成功后才显示成功。打开文件、写入或关闭失败会显示失败，目的地可能留下不完整文件，但应用内配置不会改变。

这不是键盘页导出或整应用备份；文件不包含剪贴板历史、输入记录、引擎资源、页面布局或其他设置。活动只保留“正在等待目标”的状态，不把配置文字塞入页面重建状态。

## 验证入口

先按 [测试流程](testing.md) 完成主机检查，再通过保护入口运行 `shortcut-export` 专项。自动测试仅使用合成配置、内存输出流及拦截后的文件选择请求，不实际操作系统文档界面或其他应用文件。系统文件选择器和不同文档提供方的实际保存由维护者手动验证，不能用内存流检查替代。
