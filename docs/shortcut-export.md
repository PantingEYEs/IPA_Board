# Shortcut 配置导入与导出

在 **Shortcut Management → Export configuration** 选择文件保存位置。默认文件名为 `ipa_board_shortcuts.json`，成功后页面显示 **Shortcut configuration exported.**；取消和失败分别提示，不修改已保存配置，也不执行任何绑定。

文件包含目标确认时已保存的 Shift／Ctrl 映射、六个多功能栏位置的绑定，以及已实现的 Replacement Text 规则。对话框中尚未保存的编辑不包含在内。

同页 **Import configuration** 可读取这类文件。读取及校验通过后，确认框列出文件包含的类别与条目数量；点击 **Replace configuration** 才写入。可以先导出当前配置留作备份。取消选择、取消确认或校验失败不会修改配置，导入不会执行任何绑定。

## 格式 v1

使用 UTF-8 JSON，顶层 `format` 为 `ipa-board-shortcuts`，`schemaVersion` 为整数 `1`，`categories` 按类别组织：

| 类别 | 内容 |
| --- | --- |
| `shift` | 按键字符串到稳定功能标识的对象；空映射为 `{}` |
| `ctrl` | 按键字符串到稳定功能标识的对象；空映射为 `{}` |
| `multifunctionBar` | 按稳定位置标识保存绑定；每个已知位置包含 `action`、完整 `text`、`textBehavior` |
| `replacementText` | 保留已有类别的 `schemaVersion: 1`、`category: "replacementText"` 及有序 `rules` 数组；没有规则时为 `[]` |

六个位置为 `left_first`、`left_second`、`left_third`、`right_first`、`right_second`、`right_third`，与页面显示标签无关。未保存的位置使用当前默认绑定，缺少 Shift／Ctrl 配置表示空映射。缺少替代文字配置会生成合法的空规则类别。

文字不使用界面预览的截断值，也不做去空白、大小写或宽度转换。换行、引号、反斜线、Emoji 和 IPA 字符均保留；UTF-16 代理项采用 JSON 转义，以免写成 UTF-8 时丢失孤立代理项。替代规则保留 ID、顺序、重复源文字和重复目标，不按源文字合并。

已保存的未知动作标识和附加 JSON 字段保留原值。类别类型或结构损坏、替代规则 ID 重复、无法识别的替代规则格式版本都会使导出失败，不用空值或默认值冒充完整导出，也不自动修复原配置。未来增加类别时须明确格式兼容语义，不能把缺少类别的旧文件视为已经包含该类别。

## 保存与边界

使用系统文件选择器创建用户指定的文档。打开选择器前检查配置可读取，选择目标后重新读取一个完整设置快照再写入；返回页面或重建活动不会执行绑定。全部写入、刷新和关闭成功后才显示成功。打开文件、写入或关闭失败会显示失败，目的地可能留下不完整文件，但应用内配置不会改变。

这不是键盘页导出或整应用备份；文件不包含剪贴板历史、输入记录、引擎资源、页面布局或其他设置。活动只保留“正在等待目标”的状态，不把配置文字塞入页面重建状态。

## 验证入口

先按 [测试流程](testing.md) 完成主机检查，再通过保护入口运行 `shortcut-export` 或 `shortcut-import` 专项。自动测试仅使用合成配置、内存流及拦截后的文件选择请求，不实际操作系统文档界面或其他应用文件。系统文件选择器和不同文档提供方的实际读写由维护者手动验证，不能用内存流检查替代。

## 导入范围与兼容性

- 顶层格式和版本必须为上述 v1，`categories` 至少包含一个已知类别。文件包含的类别整份替换，不合并条目；文件未包含的类别保持原值。显式空 Shift／Ctrl 对象或空替代规则列表会清空对应类别。
- 多功能栏类别必须包含完整六个位置，每项都有受支持的 `action`、完整 `text` 和 `textBehavior`。未知类别、位置、功能或文字行为会使整份导入失败，不跳过或改成默认值。该规则比只负责无损归档的导出更严格：由未来版本或外部工具写出的不兼容内容仍可导出，但当前版本不保证能导入。
- 按键字符串不能为空白；多功能栏文字、替代源及替代目标不超过现有的 1000 个 UTF-16 单元，替代规则 ID 不超过 100 个单元且唯一。替代规则顺序、重复内容、空白、大小写和 Unicode 不做归一化或截断。
- 文件上限为 4 MiB，使用严格 UTF-8 与 JSON 校验，拒绝重复字段、尾随内容及超过 32 层的结构。对象内支持的附加字段保存在相应类别中；顶层附加元数据不写入应用配置。错误提示不显示私人文件内容。

读取与保存放在后台，读取流成功关闭后才展示确认。已校验的内容只保留在内存中，确认时应用这份内容，不重新读取可能变化的文件。旋转保留待确认计划并重新显示确认框；进程丢失后不恢复私人配置内容，也不会自动确认导入，需要重新选择文件。若进程在已确认的保存阶段丢失，恢复页面提示检查当前配置，不声称取消后没有修改，也不自动重试写入。

确认后通过一次设置事务写入所有涉及的类别，未涉及的设置不改变。保存失败时恢复这些类别在确认时的原值；恢复失败单独提示，不能报为导入成功或保证原配置未变。成功后同页多功能栏和替代规则立即刷新。导入不包含引擎设置、键盘布局、剪贴板或输入记录，也不提供逐项合并和类别选择。

## 首次初始化默认配置

内置 [initialization/shortcuts/default.json](../app/src/main/assets/initialization/shortcuts/default.json) 使用相同格式，只包含 Ctrl 映射：`z → undo`、`y → redo`、`x → cut`、`c → copy`、`v → paste`、`a → select_all`。初始化复用导入校验与写入逻辑，不另外复制解析器；这个受信任的内置文件在新安装初始化时自动应用一次，不弹手动导入确认，也不添加 Shift、多功能栏或替代文字配置。

初始化完成后不会重放；已有 Shortcut 配置（包括主动清空或损坏的值）、旧版初始化记录或已有键盘页会阻止自动覆盖。首次失败不记为成功，后续可重试，但检测到用户配置时仍优先保留。撤销／重做动作优先请求宿主对应操作，不支持时分别发送 Ctrl+Z／Ctrl+Y；实际效果取决于编辑器，没有创建应用内撤销历史。可以将两个动作绑定到普通键、长按、滑动、Popup、Shift／Ctrl 快捷键或多功能栏。
