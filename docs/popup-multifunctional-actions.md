# 浮窗多功能操作

对应 [Issue #20](https://github.com/PantingEYEs/IPA_Board/issues/20)。每个键盘按键可独立选择 `Classic` 或 `Popup`；普通短按绑定始终独立。

## 设置入口与配置保留

在应用主页进入 **Keyboard → Keyboard Management**，点选键盘预览中的按键，在按键设置中切换多功能操作形式。

- `Classic`：使用原有长按、快速左滑和快速右滑配置；旧布局默认采用此模式。
- `Popup`：以图形编辑区域替换上述三个操作的编辑区域。运行时只使用浮窗配置，不执行保留的 Classic 配置。
- 切换形式不会删除另一形式的配置；保存、重新打开及布局导出/导入均保留两份配置。
- 初始浮窗沿用 Classic 按键预览的形状、尺寸和相对位置，内部没有项目。十字基准点对应键盘按键中心，移动它即可调整浮窗相对按键的位置。

## 图形编辑

视口只负责观察和编辑；对象可以超出视口。未选中对象时拖动空白处可平移视口；单击空白处取消选择，双击空白处将视口中心对齐基准点。平移视口不会移动已保存的对象。

| 对象 | 操作 |
| --- | --- |
| 浮窗 | 单击选中并显示顶点与形变选项；拖动允许编辑的顶点改变边界；双击规整为正方形。 |
| 基准点 | 单击选中并显示坐标线；再次单击取消选中；选中后拖动可移至浮窗外；双击移至填色区域的面积重心，零面积时使用四顶点均值。 |
| 圆形项目 | 单击选中并反色；再次单击编辑绑定与图层；选中后拖动位置或双指缩放圆形区域与图标；快速双击已选中的项目直接删除。 |

`Add Item` 在基准点新增默认大小项目，未绑定时显示 `∅`。项目图标沿用功能标志或绑定文本。图层通过 `Bring to Front`、`Move Up`、`Move Down` 调整，始终保持唯一线性顺序；浮窗置底、基准点其次、圆形项目在上。重叠时优先选最上方圆形项目。

有冲突的单击操作会等待系统双击判定结束，避免双击删除前先打开编辑框，或双击基准点前先取消选择。

## 形变约束

切换约束本身不改变形状。顶点始终为四个；`Distort` 开放全部顶点，其余模式只开放右下角顶点。

| 选项 | 拖动效果 |
| --- | --- |
| `Uniform` | 等比缩放当前轮廓，保留比例及已有扭曲。 |
| `Freeform` | 分别横向、纵向缩放当前轮廓，保留已有扭曲。 |
| `Distort` | 独立移动顶点，允许凹四边形和边相交。 |
| `Rotate` | 围绕四顶点坐标均值旋转。 |

形变及双击规整只修改浮窗边界，不联动圆形项目或基准点。自交形状统一按奇偶填充规则确定可见区域、内部、命中和保存时的重叠。

## 保存、取消与撤回

`Undo` / `Redo` 用于本次图形编辑历史；操作结束后的 Undo 提示使用独立的一次性快照。

| 操作 | 结果 | 提示中的 Undo |
| --- | --- | --- |
| `Cancel` 或系统返回 | 放弃未保存修改、退出按键设置并清空编辑历史。 | 重新打开按键设置并恢复刚才的未保存草稿。 |
| `Save` | 保存并退出按键设置，清空编辑历史。删除未绑定功能的项目，以及整个圆形范围均不与浮窗重叠的项目；保留已绑定且部分重叠的项目。 | 恢复本次保存之前的按键配置。 |
| `Reset` | 重新初始化此按键的浮窗配置，保留普通短按及 Classic 配置。 | 恢复重置之前的草稿。 |

保存后的 Undo 不会覆盖后来已更改的按键配置；发生冲突时会提示无法恢复。

## 输入时的操作

长按采用 `Popup` 的键盘按键，保持同一根手指滑入浮窗。指针覆盖项目时该项目反色，离开后取消反色；重叠处只激活最上方项目，浮窗外的项目区域不能激活。

项目功能复用现有执行实现，交互以 Classic 长按行为为准：

- 激活项目后停留、松手，分别等同于激活长按键后停留、松手。
- 离开项目但仍在浮窗内的移动、松手，分别等同于长按激活后横向滑动、松手；浮窗内空白不单独作为取消区。
- 激活项目后移出浮窗，立即按 Classic 长按后下滑处理并取消，不等待松手。返回浮窗、项目或原键盘按键也不会重新激活；松手不会补发普通短按。

这些等价关系优先于任何功能的个别预期，不统一假定“所有功能都等到松手才执行”，也不新增功能专用的撤回语义。本次功能保留现有长按逻辑；以后如需调整，应同时保持 Classic 与 Popup 行为一致。

浮窗超出可用屏幕的部分直接裁剪，不自动平移或缩小，也不改写保存的配置。编辑时的视口平移与运行时屏幕裁剪相互独立。

## 已知的共用功能缺陷

#20 回归发现，现有 `CompositionController.backspace()` 对预输入文本按 UTF-16 单元退格，删除 Emoji 等补充平面字符时可能留下半个代理对。这不是 Popup 专用行为，Classic 与 Popup 均使用该实现。用户决定暂不修复，后续需单独调整共用退格逻辑；当前等价测试只比较两种交互的文本与 composing 状态，不代表 Unicode 退格正确性已通过。
