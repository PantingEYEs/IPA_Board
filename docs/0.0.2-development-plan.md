# 0.0.2 开发计划

状态：实施中。联想、引擎开关、混输与注音实现及测试改进已进入开发工作树；当前测试入口、维护规则和回滚要求见 [测试流程](testing.md)。开发分支为 `0.0.2-dev`，开发版本为 `0.0.2-dev`（`versionCode = 2`），起点为正式版 `v0.0.1` 的 `be0119a`。以下 0.0.1 失败记录继续保留，当前结果以新流程报告为准。

## 本版目标

| 方向 | 计划范围 | 验收方向 |
| --- | --- | --- |
| 联想输入 | 在当前候选输入基础上设计上下文联想与连续输入体验，明确各语言支持范围及触发时机。 | 联想可选择上屏，连续输入与取消操作不丢失原文；用实际输入示例验证。 |
| 可插拔输入法引擎 | 统一引擎接入接口及能力声明，明确启停、切换、候选和错误处理边界，便于新增或替换引擎。 | 引擎可独立接入与切换；不可用或失败时有明确回退，不阻塞基础输入。 |
| 更流畅的符号、数字、音节混合输入 | 梳理组合输入、候选确认和直接上屏的衔接，减少切换时的输入中断。 | 用符号、数字、拼音/罗马字与 IPA 混输示例验证，不丢字、不重复提交，退格和光标行为一致。 |
| 更合理的单元测试 | 围绕可独立验证的输入状态、候选处理、引擎协议和配置规则编写单元测试；界面与设备行为由相应测试覆盖，并排查现有设备测试失败。 | 单元测试验证明确行为而非实现细节；设备测试采用稳定定位与隔离，各项历史失败有归因和处理记录。 |

具体算法、引擎加载方式和分阶段范围在实现前确定；“可插拔”不预设为运行时下载或加载第三方插件。

## 背景与处理决定

用户确认 0.0.1 在实际使用及手工设备验证中没有发现故障，并决定将自动化测试问题集中安排到 0.0.2 开发周期。保留失败记录，后续区分过时断言、测试环境/时序问题和实际功能缺陷，不直接把所有失败视为产品故障，也不在未经排查时标记为已通过。

## 执行顺序与验收

1. 已从正式版 main 创建 0.0.2-dev；本次提交设置开发版本与计划，后续为四项目标拆分工作项并确定验收示例。
2. 明确显示名、文件名、空白布局、长按/滑动与快捷键行为的预期，优先修正与当前产品行为不符的测试。
3. 对剩余失败逐项复现；为时序或状态问题建立可靠等待和测试隔离，避免单纯增加延迟或删除断言来取得通过结果。
4. 若复现实际功能缺陷，修复实现并保留对应回归测试；若为环境问题，记录前置条件与复现步骤。
5. 单项复测通过后运行完整单元与设备套件，确认测试没有相互污染，并记录最终提交、设备、版本与结果。
6. 按明确的验收示例实施联想输入、引擎接口和混合输入改进；每项功能验证后以 --no-ff 合入开发分支。
7. 将已完成的功能与测试改进写入 0.0.2 更新日志；未完成项继续保留在计划中。

验收目标：本次 17 项失败各有明确归因和处理记录，完整设备套件通过；如存在有意保留的限制，记录原因及覆盖范围，不将其写成“全部通过”。

## 0.0.2 测试审计结果（2026-10-03）

历史 17 项失败所覆盖的现行合同已在 API 35 ARM64 专用模拟器的完整回归中通过。原实体测试机未重新验证，不能将模拟器结果替代其兼容性结论。

| 归因 | 处理结果 |
| --- | --- |
| 产品缺陷 | Clear Keys 未保存撤销快照，按用户确认修复并保留撤销用例。额外修复快捷粘贴关闭后旧回调仍可用、按键编辑类型变化后动作按钮被裁切的问题，并保留回归断言。 |
| 行为合同 | 用户确认 Ctrl+Backspace 保持普通退格，旧按词删除断言替换为普通 Unicode 删除、无 Ctrl 的 fallback 事件及消耗 Ctrl 状态。空白布局保留默认空格/滑动映射，显示名与文件名分开验证。 |
| 测试夹具 | 实际手势入口需启用普通点击；切换页需先加入当前页组。沿用事件和有界条件等待，修复 Emoji 网格布局、IME 显示、候选节点重绘及屏外位置问题；不删除输入结果或手势断言。 |
| 目录与异步假设 | Emoji 预期取自当前目录及分类，移除固定版本/数量。E5 关闭后的原生引擎局部回复不能当作完整基础顺序，等待原顺序恢复后再核验。 |

当前主机 85 项 JVM 测试、47 项流程/清单测试通过，设备完整套件 141 项通过且回滚校验完成。新测试入口、强制备份/恢复/删除规则、套件登记和后续维护要求见 [测试流程及验证记录](testing.md)。这些结果来自开发工作树，尚未提交或作为正式版本发布。
