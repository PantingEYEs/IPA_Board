# 地球拼音（Terra Pinyin）

在 **Engine → Engine Management → Syllable Engines → Rime → Pinyin scheme** 选择 **Terra Pinyin (地球拼音)**。目前同时保留 **Luna Pinyin (朙月拼音)**，未设置时仍沿用朙月拼音，升级不会替用户改选方案。中文转换总开关同时控制拼音与注音候选；关闭时仍保留方案选择，中文续写有独立开关。

## 输入声调

声调键写在音节末尾：

| 声调 | 默认键 | 示例 | 可选替代键 |
| --- | --- | --- | --- |
| 一声 | `-` | `ma-` | `;` |
| 二声 | `/` | `ma/` | 无，仍用 `/` |
| 三声 | `<` | `ma<` | `,` |
| 四声 | `\` | `ma\` | `.` |

例如 `ni<hao<` 表示带调的“你好”；`nihao` 可省略声调，单引号可分隔音节，如 `xi'an`。声母简写和拼写纠错由当前方案自己的规则定义，没有独立纠错开关。应用保留用户输入的大小写和声调原文，仅在原生查询时编码；部分候选只消费明确匹配的原文范围，剩余声调和后缀继续待输入。

**Alternative tone keys (; , .)** 默认关闭，只在选择地球拼音时显示。开启后，音节后的分号、逗号、句号可分别参与一声、三声、四声的中文候选查询，因此可能不再被该中文候选当作普通标点。`>` 和数字 `1`–`4` 不是此入口的声调键。原样提交及其他语言引擎继续按各自规则处理；纯标点或不符合声调语法的输入不会被转换层静默删去。

## 设置和预编辑

方案与替代键是应用级设置，分别存为 `rime_pinyin_scheme`（方案 ID）和 `rime_terra_alternative_tones`（布尔值）。它们不属于键盘页的引擎开关绑定，也不进入 Remote Keyboard Mode 的引擎开关恢复记录。切换到朙月拼音会保留替代键选项，返回地球拼音时继续使用；关闭中文转换不会重置这些选项。

切换方案或替代键时，待输入原文、虚拟光标和已有内联 composing 范围保持不变，候选重新查询。旧查询回复和旧候选按钮均失效，即使重新查询得到的候选文字相同，也不能通过旧按钮提交。这个操作不提交原文、不改写编辑器，也不剥除已经输入的声调符号。非内联模式同样保留浮窗里的原文和光标。

保存失败会尝试恢复旧值并刷新控件；恢复也失败时明确提示检查当前选择。缺失、未知或类型不正确的旧配置只在设置读取层采用兼容默认：朙月拼音、替代键关闭，不自动改写原配置。

## 资源独立性与失败行为

地球拼音使用独立的 `terra_pinyin` 方案及其原生带调字典；注音的 `bopomofo` 方案共享这份字典。它们共用 Rime 运行库、OpenCC 和中文续写词料，不需要朙月拼音的 schema、dictionary、prism 或 session。朙月拼音目前作为兼容选项保留，默认值集中在设置层；方案列表由注册项生成。

资源部署目录按注册方案集合区分，不复用旧部署中的朙月拼音缓存来满足依赖。各方案会话按需创建；中文续写直接使用共享词料，不为预测打开拼音会话。上游方案保留原文件，通过独立 custom 配置禁用学习与补全；来源、版本及许可见[引擎接入说明](engine-integration.md)，资源摘要由 `tools/engine-assets.lock.json` 锁定。

明确选择的方案加载或查询失败时报告不可用，不静默切换到朙月拼音或其他方案；原文保留，用户仍可原样提交或手动选择其他可用方案。方案自身故障与其他方案隔离；共享运行库或 OpenCC 初始化失败仍属于共享后端故障。设置读取的旧值回退不等于运行时故障回退。

## 验证入口

先完成主机检查，再通过 `tools/regression.py` 运行 `terra-pinyin` 专项；用例分层、设备状态保护和结果记录规则见[测试流程](testing.md#地球拼音专项)。此文档描述功能合同，不代表所有设备、编辑器或 ABI 已验证通过。
