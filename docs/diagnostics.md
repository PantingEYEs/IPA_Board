# 可关闭的错误诊断

Engine Management 底部的 **Debug diagnostics** 默认关闭，debug 和 release 均不自动开启。开启后向 Logcat 的 `IPABoardDiagnostics` 标签输出加载阶段与固定错误码；不写日志文件、不上传数据。关闭会立即停止本进程后续输出，并通过独立控制消息通知已绑定的引擎进程，包括正在加载但尚未回复的引擎。

诊断开关独立于各引擎功能开关。关闭日志不关闭词库或模型，也不取消输入回退。引擎失败时，状态栏显示语言与失败阶段，例如 `ZHUnavailable (schema selection)`；失败引擎不提供候选，其他引擎和原文提交仍可使用。E5 失败时保留原生候选。进程内已有的加载／查询熔断仍保留，避免反复初始化原生运行时；关闭再打开语义引擎可以创建新的语义服务，原生运行时需要进程重建才能重新尝试。

## 记录范围

| 链路 | 可定位的阶段 |
| --- | --- |
| Rime | 原生库、C API/ABI、资源部署、运行时、方案编译、会话、方案选择、OpenCC、延迟加载的联想语料、查询 |
| Mozc | 数据部署与原子发布、JNI 运行时初始化、查询；JNI 内部加载库与初始化合并为 runtime initialization |
| LatinIME | 原生库、词典部署/发布、词典句柄、键盘映射、查询 |
| E5 | ONNX 环境、清单、目录/锁、模型重组/校验/发布、校准数据、分词器扩展与会话、模型会话、推理、清理 |
| 引擎通信 | 绑定被拒绝或抛异常、请求/回复发送失败、服务断开/绑定失效/空绑定、候选或分数响应格式错误 |
| 其他必要边界 | 布局存储回退、Emoji 安装目录回退与更新失败、颜文字读写、短信自动填充启动、最新版本元数据查询失败 |

事件仅由固定的 `component/stage/outcome/kind` 枚举组成，例如 `SEMANTIC/MODEL/FAILURE/NATIVE_LINK`。不传入 Throwable、异常 message/stack trace、输入/上下文/候选/词向量、剪贴板/短信、私人配置、文件名/路径/URI、下载地址或响应内容。原生库自身的内部日志由其实现控制，此开关只控制本项目新增及替换的诊断输出。原生硬崩溃通过服务断开检测，不声称能在 Kotlin 中捕获 SIGSEGV。

正常加载记录 `START` / `READY`；查询、取消、无候选、不支持的输入、缺少可选安装文件、过期结果和关闭引擎都不作为错误。相同 component/stage/kind 的失败每进程每 60 秒最多输出一次，成功恢复后可再次报告；去重缓存限 128 项，关闭时清空。诊断 sink 自身失败不会改变业务结果。

## 维护和剔除

- `diagnostics/DiagnosticReporter.kt` 管理固定词汇、失败分类、嵌套阶段、限频和无副作用输出；`diagnostics/AppDiagnostics.kt` 是唯一 Logcat 适配器、模式入口及请求快照定义。
- 所有接入附近标注 `// DIAGNOSTICS:`。可用 `rg -n 'DIAGNOSTICS|AppDiagnostics|DebugDiagnosticsSettings' app/src/main` 查找，包括资源和管理页入口。
- 运行时停止：关闭 Debug diagnostics。编译时统一禁用：把 `AppDiagnostics.LOGGING_AVAILABLE` 改为 `false`，同时隐藏管理页入口；无需修改引擎代码。
- 删除可选日志实现：将中央适配器的 sink 替换为无操作，并删除管理页控件、文字和模式快照接入。阶段包装可逐处还原为原操作；保留错误码类型或改回固定失败状态，继续保留绑定隔离、原文/离线回退、文件事务和必要清理，不能把这些错误处理随日志一起删掉。
- 新增阶段用固定枚举，不添加任意字符串字段；不要在调用侧加入独立 `Log` 或 `printStackTrace`。网络错误继续使用离线回退，不把公网可用性作为回归成功条件。

JVM 回归检查关闭、嵌套定位、去重/恢复、异常分类、隐私及失败 sink。Android 合同验证独立持久化/进程快照、真实部署目录故障、服务绑定拒绝/失效回退和 UI 操作；实际引擎与 E5 成功链路由原有套件覆盖。设备运行遵守 [测试流程](testing.md)，通过外部备份保护执行，结束后验证回滚并删除备份。
