## 发布目标：官方源码构建与许可证迁移

**0.0.4 的发布目标是成为 IPA Board 首个不再按 GPL-3.0 整体发行的版本。** 发布前完成引擎构建链替换、接入代码与依赖的许可核验，再由维护者敲定后续具体协议。本计划不提前选择新协议，也不表示当前开发版已经完成许可变更；既有版本及第三方的原始许可资料继续保留。

[#49](https://github.com/PantingEYEs/IPA_Board/issues/49) 已在独立 chinese 分支完成官方 librime 1.17.0／OpenCC 1.4.2 构建，固定 `073aabe` 产物及新 JNI 已通过 [PR #60](https://github.com/PantingEYEs/IPA_Board/pull/60) 完成应用接入并关闭 Issue；不使用 Trime 编译脚本、组合二进制或 JNI 封装。自动专项及维护者实测通过，见 [接入说明](rime-upstream.md)。[#52](https://github.com/PantingEYEs/IPA_Board/issues/52) 则从 HeliBoard 中选择适用 Apache-2.0 的 LatinIME 原生核心及必要组件独立构建，不能把 HeliBoard 整体许可直接套用到每个文件，也不能将完整应用或未核验的 GPL 接入代码一起带入。

源码自行编译、随包交付与项目许可迁移是不同任务；构建来源或打包方式改变本身不代表许可迁移已经完成。新协议确定前需明确实际采用的源码、修改、JNI/桥接、词表及依赖的授权范围。

### 2.2 LatinIME 与新协议的边界

HeliBoard 的[整体许可说明](https://github.com/HeliBorg/HeliBoard#license)与其 AOSP 来源文件的独立许可应分别判断；例如原生[构建清单](https://github.com/HeliBorg/HeliBoard/blob/main/app/src/main/jni/NativeFileList.mk)及[原生代码](https://github.com/HeliBorg/HeliBoard/blob/main/app/src/main/jni/src/suggest/core/layout/proximity_info_state.cpp)明确标注 Apache-2.0。本计划保留从 HeliBoard 获取 LatinIME 源码的路线，要求按实际采用的核心、JNI、头文件和依赖确认范围，不将整个 HeliBoard 应用一并移入。

本项目现有 `BinaryDictionary.java`、`DicTraverseSession.java` 等接入声明中有 `Apache-2.0 AND GPL-3.0-only` 标记，需核验其来源及所需内容，并在迁移时采用授权明确的来源或自行重建相应接入代码；不得只删除许可标记。现成词表的许可也需独立确认，保持“不自行编译 `main_en-US.dict`”的技术决定。完成这些工作后，再敲定 IPA Board 后续具体协议。

### 2.3 随包交付与既有用户升级

**正式 APK 继续包含第三方引擎、匹配的原生桥接、词典、E5 模型及分词资源；首次使用不要求下载这些组件。** 应用在后台部署内置资源并本地查询；更换的是构建来源和适配方式。

- 构建产物、JNI、数据格式、ABI 和加载路径配套交付，区分配置开启与运行就绪，显示加载失败的具体阶段。
- 识别新构建与旧部署缓存，按构建身份或新部署代际迁移；保留用户布局、页组绑定、引擎开关和其他设置，不将旧来源二进制冒充新产物。
- 保留全部引擎关闭、资源损坏和加载失败时的原文输入／可用引擎回退，避免单一引擎故障导致输入法整体崩溃。
- 原 [#53](https://github.com/PantingEYEs/IPA_Board/issues/53) 的“第三方资源移出 APK、应用内下载后安装”方案不再作为本版任务或发布条件。此次只调整本地文档，GitHub Issue 的范围与状态另行处理；其他引擎未来是否增加在线更新另按独立需求确定。
- IPA Engine 已交付的独立更新继续保留：GitHub Releases 发现、哈希／兼容校验、隔离验证、失败保留旧资源，以及默认关闭的 **Allow Pre-release updates**。关闭预发布不会回退已安装版本；独立词典更新及活动代际隔离保持不变，详见 [IPA 资源说明](ipa-updates.md)。

### 2.4 对齐、接入与发布验收

#49 经 PR #60 合入后，当前应用／测试 APK 的原生条目为 **15+1**，全部通过 ELF LOAD／RELRO 与两包 16KB ZIP 对齐检查；旧 JNA 与独立桥接已移除。**48 项 JVM、80 项工具测试、严格 API 36／x86_64／真实 16KB 专项 105/105** 通过，另补做迁移 **3/3** 与软件／私有数据备份恢复往返验证；两轮均恢复校验并删除备份。预览版保留数据更新，维护者实测报告使用无问题。该反馈与自动化环境分别记录，不外推为 ARM64 自动回归、4KB、其他 API、完整编辑器或 release／AAB 认证。

Mozc 与 Extensions 已通过源码构建完成 16KB 对齐修复。#51 接入后的 debug 应用／测试 APK 共 **19+1 个原生条目**全部通过 ELF LOAD／RELRO 检查，两份 APK 通过 16KB ZIP 对齐；未排除任何正常原生依赖。禁用页大小兼容模式后，在 **API 36／x86_64／真实 16384 字节页**进程执行专项 **38/38 通过**，相关 **13 项工具、34 项 JVM**通过。实际记录见[测试流程](testing.md)。这不代表正式签名 release、AAB 或 ARM64 真机运行已验证，也不宣称排序效果改善。

#51 按维护者确定的范围，仅以真实 16KB 页环境验收，未追加 4KB 回归。此前的新旧输出对照与 #50 的 4KB 记录继续保留历史事实，不作为当前支持承诺。后续替换随包运行库或依赖时，仍按 [Android 官方说明](https://developer.android.com/guide/practices/page-sizes)分别核查静态 ELF／ZIP 和真实进程运行，不沿用未执行的平台结论。

构建与接入分别验证拼音/注音、简繁、日文转换/预测、英文补全/纠错/预测以及 E5 分词排序，保留过期结果拒绝、全引擎关闭、损坏资源及失败回退测试。最终检查发布 APK 的原生库、assets 和传递 AAR 内容，确认应随包的资源完整且来源、JNI 和数据版本匹配，不混入旧 Trime 或其他 App 提取的运行库；ONNX Runtime 官方主库 AAR、现成词表和模型按上述例外保留。剩余源码构建、许可来源核验、适配回归及新协议决定仍为发布前工作；通用资源下载或减小 APK 不再是完成条件。各项以实际记录验收，不把某个引擎的通过外推为所有引擎或平台已验证。

## 4. 宽屏键盘：Stretch 与 Split

待实现的 [#34](https://github.com/PantingEYEs/IPA_Board/issues/34) 解决双手握持时中间列按键难以触达的问题，当前确认范围为逐 **Keyboard Page** 的 Split，默认关闭。Stretch 仍是计划方向，不属于 #34 的已确认交付范围。

- 每页独立保存 Split 配置；启用且达到宽度阈值时分为左右两侧，低于阈值时恢复普通布局但保留设置，不以横竖屏方向代替宽度判断。
- 显示方式切换保留已有按键、功能绑定和页面配置，不以重新初始化键盘实现布局切换。
- 一并验证按键预览、Popup、Pointer Location、候选栏和多功能栏在宽屏下的定位与触摸。
- 横竖屏或可用宽度变化时，保留预输入、当前页与必要的界面状态。

实施前仍需确认：宽度阈值及测量依据、各行分割位置、中央间距、奇数键行的中间键归属，以及空格等宽键的处理。不预先把某种分割算法写成必须采用的实现。

## 5. 优化多功能操作体验

[#10](https://github.com/PantingEYEs/IPA_Board/issues/10) 的四方向连续光标及后续长按队列优化已交付；以下行为继续作为维护合同，其他体验改动按具体问题确认。

- 连续移动与已有单步光标操作保持独立，可通过现有功能绑定机制使用。
- 明确持续执行的启动、重复、松手、移出、取消与文本边界行为，复用现有持续操作机制中适用的部分。
- 验证与预输入、选区及不同编辑器的交互，防止重复提交或意外修改文本。
- 其他多功能操作体验调整先确认具体问题与范围，不由父任务名称自动扩展要求。

#10 的实现新增 Continuous Cursor Up / Down / Left / Right，复用原方向键执行逻辑及 Continuous Delete 的重复机制；支持独立短按/长按、Popup 和多功能栏绑定，未修改默认布局。此实现不改变下面确认保留的退格行为。

**保留现有预输入按 UTF-16 单元退格的行为。** 用户已明确选择保留，包括可能留下半个代理对的情况；本版不把它作为稳定性缺陷修复，也不借连续光标或 Popup 改造改变它。历史计划中的相关修复建议不作为 0.0.4 的要求。

#38 已支持中文简繁（拼音／注音）和日文前缀选词，已选段立即上屏，剩余编码待输入；原生覆盖范围用于后续候选和替代文字，不按候选文字长度推算。内联预输入保留含两端点的光标范围，完全越界则原位上屏；紧贴起点退格删除前文并保留后缀。新增非内联模式另按自身缓冲、确认与取消规则处理，不能混用内联规则。详见 [引擎接入说明](engine-integration.md)。
