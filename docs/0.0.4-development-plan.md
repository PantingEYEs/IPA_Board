# 0.0.4 开发计划

状态：开发中，#10 连续光标与长按队列、#16 Rime 批量候选优化已合并；#15 已加入启动补读及历史管理，间歇性故障仍在调查。其余目标按 Issue 分步推进。开发分支为 `0.0.4-dev`，Android `versionName = 0.0.4-dev`、`versionCode = 4`，从 `v0.0.3` 的 `main` 合并提交 `fbbb642` 开始。计划整理日期：2026-10-25，更新日期：2026-10-27；实际验证范围见 [测试记录](testing.md)。

## 发布目标：官方源码构建与许可证迁移

**0.0.4 的发布目标是成为 IPA Board 首个不再按 GPL-3.0 整体发行的版本。** 发布前完成引擎构建链替换、接入代码与依赖的许可核验，再由维护者敲定后续具体协议。本计划不提前选择新协议，也不表示当前开发版已经完成许可变更；既有版本及第三方的原始许可资料继续保留。

Rime/OpenCC 改为从各自官方仓库拉取源码，自行构建并维护 IPA Board 的桥接和适配，不使用 Trime 提供的编译脚本、JNI 桥接或相关封装工具。LatinIME 则从 HeliBoard 中选择适用 Apache-2.0 的原生核心及必要组件独立构建，不能把 HeliBoard 整体许可直接套用到每个文件，也不能将完整应用或未核验的 GPL 接入代码一起带入。

源码自行编译、运行资源改为下载，与项目许可迁移是相关但不同的任务；不能把“APK 内不包含引擎”单独作为已经满足新许可目标的依据。新协议确定前需明确实际采用的源码、修改、JNI/桥接、词表及依赖的授权范围。

本版围绕以下七个方向推进。具体需求、未决交互及验收通过独立 Issue 确认；本文不表示所有目标已经实现或验证。

| 方向 | 本版目标 | 范围边界 |
| --- | --- | --- |
| Remote Keyboard 蓝牙键盘 | 先在 App 内连接目标设备并发送键盘输入 | 随输入法服务快捷开启留待后续逐步迁移 |
| 第三方引擎构建、下载与安装适配 | 从指定官方源码构建资源，应用内下载、适配与安装；完成许可迁移 | 第三方引擎及专用资源不再随 APK 提供；IPA Engine 与配套词典继续内置 |
| About | 展示必要资讯，浏览器跳转仓库及 Releases 反馈入口 | 版本讨论使用 Discussion |
| 宽屏键盘 | 允许配置强行拉伸（Stretch）或分体（Split） | 重点解决双手握持时中间列难以触达 |
| 优化多功能操作体验 | 将连续光标控制作为子问题推进 | 其他体验改动另行确认，保留现有退格行为 |
| Shortcut 配置导出 | 导出现有 Shortcut 配置，建立可扩展格式 | 替代文字属于未来版本的 Shortcut 能力 |
| 基础输入稳定性 | 调查并修复已有输入可靠性问题 | 不包含改变现有 Unicode 退格行为 |

## 1. Remote Keyboard：先在 App 内实现蓝牙键盘

延续 [#4](https://github.com/PantingEYEs/IPA_Board/issues/4)，让手机上的 IPA Board 作为蓝牙键盘向连接的电脑等目标设备发送输入。

- 首先在 App 内提供连接、连接状态、键盘输入及断开操作，先验证完整的实际连接链路。
- 区分普通按键、修饰键和组合键的发送；IPA、中文、Emoji 及剪贴板原文传输的支持范围需要单独验证，不能由普通按键发送成功推断。
- 连接管理与现有 Remote Keyboard Mode 的引擎状态快照保持独立；连接失败或断开不应破坏本地输入与原有引擎配置。
- 后续逐步迁移到随输入法服务快捷开启。本阶段不要求完成这一入口，也不将 Wi-Fi 传输一并设为完成条件。

先验证目标设备的蓝牙能力、权限及 App 生命周期限制，再在对应 Issue 中确定支持矩阵与输入形式。

## 2. 第三方引擎：源码构建、独立资源发布与客户端下载

### 2.1 来源与构建范围

| 资源 | 确定的来源 | 0.0.4 要完成的工作 |
| --- | --- | --- |
| Rime/librime | [rime/librime](https://github.com/rime/librime) | 直接拉取官方源码构建原生引擎，迁移现有批量候选接口与接入逻辑，提高与 IPA Board 的适配程度 |
| OpenCC | [BYVoid/OpenCC](https://github.com/BYVoid/OpenCC) | 从官方源码独立构建，维护简繁转换接口及所需数据，替代 Trime 组合库中的实现 |
| Mozc | [google/mozc](https://github.com/google/mozc) | 从官方源码构建日文引擎及必要接口，解决现有原生库的 ELF 段对齐问题 |
| ONNX Runtime Extensions | [microsoft/onnxruntime-extensions](https://github.com/microsoft/onnxruntime-extensions) | 从官方源码构建所需扩展，解决现有语义分词扩展库的 ELF 段对齐问题 |
| LatinIME | [HeliBorg/HeliBoard](https://github.com/HeliBorg/HeliBoard) 的 LatinIME 原生核心 | 选取并独立构建 Apache-2.0 代码及经过核验的必要依赖，调整 IPA Board 的英文接口，提高适配程度 |
| OpenBoard 英文词表 | 继续使用现成的 `main_en-US.dict`，[保留当前来源链](../app/src/main/assets/licenses/English-dictionary-source.txt) | 不自行编译词表；单独维护其下载、格式兼容、哈希与许可信息 |

Rime/OpenCC 不再使用 Trime 的组合二进制、构建或桥接工具；自行维护必要的 Android 构建与桥接代码。原生批量读取应保留 #16 已验证的输入覆盖检查、前缀保留及查询效率，不能因更换构建来源退回逐候选完整重放。Mozc、LatinIME 与 Extensions 也应以所选源码构建产物替代当前从第三方 APK/AAR 取得的相应预编译库。

官方仓库是上述组件的**源码来源**；编译在项目构建侧完成，客户端下载对应构建产物，不要求手机编译源码。记录固定源码提交、子模块、构建工具、适配补丁、ABI 与产物哈希。资源产物的发布位置、清单格式及下载入口在实现 Issue 中确定，不在此提前指定仓库目录或服务平台。

E5 模型、分词资源及 ONNX Runtime 等运行依赖继续纳入此前的拆分计划；本次明确自行编译的是 ONNX Runtime **Extensions**，不额外要求重编译 ONNX Runtime 主库。IPA Engine 与其配套词典维持已确认的内置安排。

### 2.2 LatinIME 与新协议的边界

HeliBoard 的[整体许可说明](https://github.com/HeliBorg/HeliBoard#license)与其 AOSP 来源文件的独立许可应分别判断；例如原生[构建清单](https://github.com/HeliBorg/HeliBoard/blob/main/app/src/main/jni/NativeFileList.mk)及[原生代码](https://github.com/HeliBorg/HeliBoard/blob/main/app/src/main/jni/src/suggest/core/layout/proximity_info_state.cpp)明确标注 Apache-2.0。本计划保留从 HeliBoard 获取 LatinIME 源码的路线，要求按实际采用的核心、JNI、头文件和依赖确认范围，不将整个 HeliBoard 应用一并移入。

本项目现有 `BinaryDictionary.java`、`DicTraverseSession.java` 等接入声明中有 `Apache-2.0 AND GPL-3.0-only` 标记，需核验其来源及所需内容，并在迁移时采用授权明确的来源或自行重建相应接入代码；不得只删除许可标记。现成词表的许可也需独立确认，保持“不自行编译 `main_en-US.dict`”的技术决定。完成这些工作后，再敲定 IPA Board 后续具体协议。

### 2.3 应用内下载与安装

**上述第三方引擎、专用原生桥接/运行库、配套词典和模型资源，改为通过应用内下载搭载，不再直接包含于正式发布 APK。** `main_en-US.dict` 虽不自行编译，也属于下载资源。通用界面依赖和安装管理代码不因引擎拆包而一并删除。

用户流程为：**选择资源 → 下载对应构建产物或现成词表/模型 → 内置程序校验、适配与安装 → 显示成功或具体失败阶段**。本节以源码构建产物替代原计划中直接适配上游 App 预编译附件的方式；不再要求从 Trime 等应用 APK 中提取运行库。

- 检查版本、完整性、资源格式、ABI、引擎接口及桥接版本匹配，分别展示下载完成与安装可用。不承诺兼容任意未来上游版本。
- 引擎专用桥接随匹配资源安装，处理本地加载路径与依赖顺序；资源缺失时不得因硬链接依赖缺失导致应用或输入法启动崩溃。
- 安装、更新或切换失败保留原有可用版本；切换成功后才清理旧资源。
- 区分未安装、配置关闭、加载中和加载失败。未安装或全部关闭时保留原文输入；页面绑定不能将配置开启误报为引擎就绪。
- 迁移既有部署资源与配置，保留页绑定和用户设置；旧来源的二进制不能不经识别就冒充新构建资源。
- 查询在本地执行；保留 E5 默认关闭行为。来源、构建版本及适用许可可在客户端查阅。

### 2.4 对齐、接入与发布验收

Mozc 与 ONNX Runtime Extensions 的目标是修复 **16KB 页设备所需的 ELF 段对齐**，不是只调整压缩包。按 [Android 官方说明](https://developer.android.com/guide/practices/page-sizes)检查两种支持 ABI 的 ELF `PT_LOAD` 等加载要求，并在实际 16KB 页环境验证加载与输入/语义分词；静态对齐通过不等于运行验证通过。其余下载库和依赖也应一并核查，防止主库修复后仍被依赖库阻断。

构建与接入分别验证拼音/注音、简繁、日文转换/预测、英文补全/纠错/预测以及 E5 分词排序，保留过期结果拒绝、全引擎关闭、损坏资源及失败回退测试。最终检查发布 APK 的原生库、assets 和传递 AAR 内容，确认已拆分的资源没有被重新打包进去。许可来源核验、资源独立下载、适配回归及新协议决定都是 0.0.4 发布前的完成条件；本次仅更新计划，不代表已执行构建或拆包。

## 3. About 子页面

在 App 内提供 About 页面，展示应用版本等必要资讯，以及项目与第三方引擎、模型和词典的许可、来源信息。

- 仓库超链接调用浏览器打开 GitHub 仓库。
- 用户反馈入口跳转仓库的 **Releases**，围绕发布版本使用已开启的 **Discussion** 讨论。
- 展示的版本与实际安装版本一致；外部跳转失败时提供反馈，保持应用可继续使用。

不在本目标中增加内置网页浏览器、自动上传反馈或自动更新应用的功能。

## 4. 宽屏键盘：Stretch 与 Split

重点解决双手握持时中间一纵列按键难以触达的问题，允许用户选择强行拉伸（Stretch）和分体（Split）。

- Stretch 将键盘布局拉伸到可用宽度；Split 将按键分配到左右两侧，形成便于双手操作的布局。
- 显示方式切换保留已有按键、功能绑定和页面配置，不以重新初始化键盘实现布局切换。
- 一并验证按键预览、Popup、Pointer Location、候选栏和多功能栏在宽屏下的定位与触摸。
- 横竖屏或可用宽度变化时，保留预输入、当前页与必要的界面状态。

以下交互尚未指定，实施前在 Issue 中确认：配置属于全局、页组还是单页；宽屏判定与默认模式；分割位置及间距；奇数键行的中间键归属；空格等宽键的处理。不预先把某种分割算法写成必须采用的实现。

## 5. 优化多功能操作体验

将“优化多功能操作体验”作为父任务，连续光标控制作为其中的子问题，延续 [#10](https://github.com/PantingEYEs/IPA_Board/issues/10) 的四方向连续光标功能。

- 连续移动与已有单步光标操作保持独立，可通过现有功能绑定机制使用。
- 明确持续执行的启动、重复、松手、移出、取消与文本边界行为，复用现有持续操作机制中适用的部分。
- 验证与预输入、选区及不同编辑器的交互，防止重复提交或意外修改文本。
- 其他多功能操作体验调整先确认具体问题与范围，不由父任务名称自动扩展要求。

#10 的实现新增 Continuous Cursor Up / Down / Left / Right，复用原方向键执行逻辑及 Continuous Delete 的重复机制；支持独立短按/长按、Popup 和多功能栏绑定，未修改默认布局。此实现不改变下面确认保留的退格行为。

**保留现有预输入按 UTF-16 单元退格的行为。** 用户已明确选择保留，包括可能留下半个代理对的情况；本版不把它作为稳定性缺陷修复，也不借连续光标或 Popup 改造改变它。历史计划中的相关修复建议不作为 0.0.4 的要求。

## 6. Shortcut 配置导出

Shortcut 是快捷输入与功能配置的统一概念，当前包含 Shift/Ctrl 快捷键映射和多功能栏绑定；未来还会加入替代文字等快捷输入能力。

- 本版导出当前已保存的 Shortcut 配置，完整保留功能标识、绑定文本及已有相关选项。
- 文件包含格式版本并按类别组织，便于未来加入替代文字时继续扩展和识别旧文件。
- 替代文字功能本身留给后续版本，不因为预留导出格式就列为本版必须交付的功能。
- 配套导入、冲突处理及部分恢复是否纳入本版，在具体 Issue 中另行确认；当前已确认目标是导出。

## 7. 提高基础输入稳定性

按独立问题调查以下已有反馈，依据复现与验证结果确定本版交付，不预先指定根因：

- [#15](https://github.com/PantingEYEs/IPA_Board/issues/15)：剪贴板偶发缺少最新复制内容。
- [#16](https://github.com/PantingEYEs/IPA_Board/issues/16)：Rime 原生批量候选优化已由 PR #31 合并，维护者反馈更快并关闭 Issue。后续官方源码构建须保留该成果；受控实机录屏范围仍按测试记录解释。
- [#17](https://github.com/PantingEYEs/IPA_Board/issues/17)：Notion Android 特定代码区位置提前提交首字符。
- 已记录的输入法窗口等待问题：区分测试环境、窗口生命周期与实际输入故障，不通过放宽等待时间宣称修复。

调查记录区分已观察事实、假设与确认原因；修复保留相应回归。现有 UTF-16 退格行为不在此清单内，按上一节的用户决定保留。

## 推进与验证

优先确定各引擎的源码与许可子集，完成不依赖 Trime 的 Rime/OpenCC 构建及桥接迁移，再推进 Mozc/Extensions 对齐修复、LatinIME 适配与独立资源下载；许可核验完成后敲定新协议。蓝牙可行性验证可并行开展，其余目标按独立 Issue 推进。连续光标归入多功能操作父任务，尚未确认的交互在实现前询问，不把可选建议转成硬性要求。

- 主机侧先验证配置、资源校验、安装事务、失败回退及旧数据兼容；设备验证按影响选择套件并记录实际 API、ABI、目标端与编辑器。
- 所有安装 APK、instrumentation 和输入法切换检查遵守 [AGENTS.md](../AGENTS.md) 与 [测试流程](testing.md)：测试前备份 IPA Board 软件及私有数据，结束后恢复、校验并删除备份；恢复失败保留备份和恢复入口。
- 仅在测试拥有的配置与文本上验证；不把公网可用性作为常规回归成功条件。官方源可达性与离线安装故障分别记录。
- 发布包仍由维护者明确指示后构建；编译、签名校验、用户验收与设备回归分别记录，不相互代替。
- `minSdk=26` 仅放宽安装门槛，最低适配 API 仍为 35；本版计划不自动承诺 API 26 或鸿蒙运行兼容。

版本收尾时更新 README、changelog、Release Notes 和实际验收范围，明确未完成项，不将开发目标写成已交付能力。
