# 0.0.4 开发计划

状态：开发中。连续光标与长按队列、Rime 批量候选、Shortcut 导入／导出、页组传输、地球拼音、蓝牙键盘首版，以及 #50 Mozc／#51 Extensions 源码构建接入已交付；#15 的补读与历史管理已加入，偶发漏读暂缓继续调查。其余目标按 Issue 推进。开发分支为 `0.0.4-dev`，Android `versionName = 0.0.4-dev`、`versionCode = 4`，从 `v0.0.3` 的 `main` 合并提交 `fbbb642` 开始。计划整理日期：2026-10-25，更新日期：**2026-11-11**；实际验证范围见 [测试记录](testing.md)。

## 发布目标：官方源码构建与许可证迁移

**0.0.4 的发布目标是成为 IPA Board 首个不再按 GPL-3.0 整体发行的版本。** 发布前完成引擎构建链替换、接入代码与依赖的许可核验，再由维护者敲定后续具体协议。本计划不提前选择新协议，也不表示当前开发版已经完成许可变更；既有版本及第三方的原始许可资料继续保留。

后续 [#49](https://github.com/PantingEYEs/IPA_Board/issues/49) 将 Rime/OpenCC 改为从各自官方仓库拉取源码，自行构建并维护 IPA Board 的桥接和适配，不使用 Trime 提供的编译脚本、JNI 桥接或相关封装工具。[#52](https://github.com/PantingEYEs/IPA_Board/issues/52) 则从 HeliBoard 中选择适用 Apache-2.0 的 LatinIME 原生核心及必要组件独立构建，不能把 HeliBoard 整体许可直接套用到每个文件，也不能将完整应用或未核验的 GPL 接入代码一起带入。

源码自行编译、运行资源改为下载，与项目许可迁移是相关但不同的任务；不能把“APK 内不包含引擎”单独作为已经满足新许可目标的依据。新协议确定前需明确实际采用的源码、修改、JNI/桥接、词表及依赖的授权范围。

本版围绕以下七个方向推进。具体需求、未决交互及验收通过独立 Issue 确认；本文不表示所有目标已经实现或验证。

## 1. Remote Keyboard：先在 App 内实现蓝牙键盘

[#35](https://github.com/PantingEYEs/IPA_Board/issues/35) 的 App 内蓝牙键盘首版已交付并关闭，维护者反馈基本功能实测可用、体验仍需改进。使用系统当前输入法，支持手动／即时发送标准 HID ASCII 和常用组合键；接收端布局与输入法决定最终文字。详情与已验证范围见[蓝牙键盘说明](bluetooth-remote-keyboard.md)。

连接管理与已有 Remote Keyboard Mode 的引擎快照保持独立；断线不覆盖恢复记录，失败或中断的输入不自动重发。此首版反馈不等于全部接收端、权限与后台异常场景已验证。

父任务 [#4](https://github.com/PantingEYEs/IPA_Board/issues/4) 保持开放：随输入法服务快捷连接、Wi-Fi、完整文字与剪贴板原文传输继续延期；不以普通按键成功推断 IPA、中文或 Emoji 原文传输已经支持。

官方仓库是上述组件的**源码来源**；编译在项目构建侧完成，不要求手机编译源码。现有 Mozc 与 Extensions 构建资料、产物分别保存在 IPA_Engine 的 `japanese`、`ranking` 分支，固定源码、工具、补丁、ABI 与摘要均已记录。面向客户端的发布清单、下载与安装入口由 #53 实现，不能把源码分支已有产物当作客户端已支持下载。

E5 模型、分词资源及 ONNX Runtime 等运行依赖继续纳入此前的拆分计划；本次明确自行编译的是 ONNX Runtime **Extensions**，不额外要求重编译 ONNX Runtime 主库。IPA Engine 与其配套词典维持已确认的内置安排。

### 2.2 LatinIME 与新协议的边界

HeliBoard 的[整体许可说明](https://github.com/HeliBorg/HeliBoard#license)与其 AOSP 来源文件的独立许可应分别判断；例如原生[构建清单](https://github.com/HeliBorg/HeliBoard/blob/main/app/src/main/jni/NativeFileList.mk)及[原生代码](https://github.com/HeliBorg/HeliBoard/blob/main/app/src/main/jni/src/suggest/core/layout/proximity_info_state.cpp)明确标注 Apache-2.0。本计划保留从 HeliBoard 获取 LatinIME 源码的路线，要求按实际采用的核心、JNI、头文件和依赖确认范围，不将整个 HeliBoard 应用一并移入。

本项目现有 `BinaryDictionary.java`、`DicTraverseSession.java` 等接入声明中有 `Apache-2.0 AND GPL-3.0-only` 标记，需核验其来源及所需内容，并在迁移时采用授权明确的来源或自行重建相应接入代码；不得只删除许可标记。现成词表的许可也需独立确认，保持“不自行编译 `main_en-US.dict`”的技术决定。完成这些工作后，再敲定 IPA Board 后续具体协议。

### 2.3 应用内下载与安装

待完成的 [#53](https://github.com/PantingEYEs/IPA_Board/issues/53) 将上述第三方引擎、专用原生桥接／运行库、配套词典和模型改为应用内下载，使其不再直接包含于正式发布 APK；**当前资源仍内置**。`main_en-US.dict` 虽不自行编译，也属于下载资源。通用界面依赖和安装管理代码不因引擎拆包而一并删除。

用户流程为：**选择资源 → 下载对应构建产物或现成词表/模型 → 内置程序校验、适配与安装 → 显示成功或具体失败阶段**。本节以源码构建产物替代原计划中直接适配上游 App 预编译附件的方式；不再要求从 Trime 等应用 APK 中提取运行库。

- 检查版本、完整性、资源格式、ABI、引擎接口及桥接版本匹配，分别展示下载完成与安装可用。不承诺兼容任意未来上游版本。
- 引擎专用桥接随匹配资源安装，处理本地加载路径与依赖顺序；资源缺失时不得因硬链接依赖缺失导致应用或输入法启动崩溃。
- 安装、更新或切换失败保留原有可用版本；切换成功后才清理旧资源。
- 区分未安装、配置关闭、加载中和加载失败。未安装或全部关闭时保留原文输入；页面绑定不能将配置开启误报为引擎就绪。
- 迁移既有部署资源与配置，保留页绑定和用户设置；旧来源的二进制不能不经识别就冒充新构建资源。
- 查询在本地执行；保留 E5 默认关闭行为。来源、构建版本及适用许可可在客户端查阅。

### 2.4 对齐、接入与发布验收

Mozc 与 Extensions 已通过源码构建完成 16KB 对齐修复。#51 接入后的 debug 应用／测试 APK 共 **19+1 个原生条目**全部通过 ELF LOAD／RELRO 检查，两份 APK 通过 16KB ZIP 对齐；未排除任何正常原生依赖。禁用页大小兼容模式后，在 **API 36／x86_64／真实 16384 字节页**进程执行专项 **38/38 通过**，相关 **13 项工具、34 项 JVM**通过。实际记录见[测试流程](testing.md)。这不代表正式签名 release、AAB 或 ARM64 真机运行已验证，也不宣称排序效果改善。

#51 按维护者确定的范围，仅以真实 16KB 页环境验收，未追加 4KB 回归。此前的新旧输出对照与 #50 的 4KB 记录继续保留历史事实，不作为当前支持承诺。后续替换运行库或下载依赖时，仍按 [Android 官方说明](https://developer.android.com/guide/practices/page-sizes)分别核查静态 ELF／ZIP 和真实进程运行，不沿用未执行的平台结论。

构建与接入分别验证拼音/注音、简繁、日文转换/预测、英文补全/纠错/预测以及 E5 分词排序，保留过期结果拒绝、全引擎关闭、损坏资源及失败回退测试。最终检查发布 APK 的原生库、assets 和传递 AAR 内容，确认已拆分的资源没有被重新打包进去。许可来源核验、资源独立下载、适配回归及新协议决定都是 0.0.4 发布前的完成条件；各项以独立任务的实际记录验收；Mozc 的构建接入不代表其他构建、资源拆包或协议迁移已经完成。

## 4. 宽屏键盘：Stretch 与 Split

待实现的 [#34](https://github.com/PantingEYEs/IPA_Board/issues/34) 解决双手握持时中间列按键难以触达的问题，当前确认范围为逐 **Keyboard Page** 的 Split，默认关闭。Stretch 仍是计划方向，不属于 #34 的已确认交付范围。

- 每页独立保存 Split 配置；启用且达到宽度阈值时分为左右两侧，低于阈值时恢复普通布局但保留设置，不以横竖屏方向代替宽度判断。
- 显示方式切换保留已有按键、功能绑定和页面配置，不以重新初始化键盘实现布局切换。
- 一并验证按键预览、Popup、Pointer Location、候选栏和多功能栏在宽屏下的定位与触摸。
- 横竖屏或可用宽度变化时，保留预输入、当前页与必要的界面状态。

实施前仍需确认：宽度阈值及测量依据、各行分割位置、中央间距、奇数键行的中间键归属，以及空格等宽键的处理。不预先把某种分割算法写成必须采用的实现。

## 5. 优化多功能操作体验

[#10](https://github.com/PantingEYEs/IPA_Board/issues/10) 的四方向连续光标及后续长按队列优化已交付；以下行为继续作为维护合同，其他体验改动按具体问题确认。

- 连续移动与已有单步光标操作保持独立，可通过现有功能绑定机制使用。
- 明确持续执行的启动、重复、松手、移出、取消与文本边界行为，复用现有持续操作机制中适用的部分。
- 验证与预输入、选区及不同编辑器的交互，防止重复提交或意外修改文本。
- 其他多功能操作体验调整先确认具体问题与范围，不由父任务名称自动扩展要求。

#10 的实现新增 Continuous Cursor Up / Down / Left / Right，复用原方向键执行逻辑及 Continuous Delete 的重复机制；支持独立短按/长按、Popup 和多功能栏绑定，未修改默认布局。此实现不改变下面确认保留的退格行为。

**保留现有预输入按 UTF-16 单元退格的行为。** 用户已明确选择保留，包括可能留下半个代理对的情况；本版不把它作为稳定性缺陷修复，也不借连续光标或 Popup 改造改变它。历史计划中的相关修复建议不作为 0.0.4 的要求。

## 6. Shortcut 配置导出
