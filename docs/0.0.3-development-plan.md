# 0.0.3 开发计划

状态：规划中，尚未实现本版新增功能。开发分支为 `0.0.3-dev`，Android `versionName = 0.0.3-dev`、`versionCode = 3`；从正式版 `v0.0.2` 的 `main` 合并提交 `54e5f04` 开始。

本版围绕八个方向推进：Issue 驱动开发、鸿蒙 4.2.0.x 兼容、无候选问题与日志管理、仪表盘、按键盘页绑定引擎、计算器、多功能栏编辑，以及正式 IPA 键盘和自研基础引擎。下面列出范围、依赖与验收条件，具体功能通过对应 Issue 分步落实。

## 1. 开发流程改为提 Issue、解决 Issue

功能、缺陷、兼容性与较大的重构先登记 Issue，再进入实现。计划中的八个方向可建立为跟踪 Issue，其下拆分可以独立验证、独立合并的小任务；不把整个版本塞进一个实现 Issue。

每个 Issue 至少包含目的、当前行为、预期行为、范围、验收条件和验证方式。缺陷增加合成复现步骤及频率；兼容性增加设备型号、完整系统构建号、实际 API/ABI 和环境限制；设计任务先明确待决定的行为合同。

建议流程：

1. 提交 Issue 并确认范围，标注 `bug` / `feature` / `compatibility` / `refactor`、优先级和 `0.0.3` 里程碑。
2. 从 `0.0.3-dev` 创建小分支，分支名关联真实 Issue 编号，例如 `codex/123-candidate-timeout`。
3. 在 Issue 中确认有争议的行为，补充必要回归，再实现最小完整变更。新增需求另开 Issue，不在原任务中无限扩展。
4. 提交或 PR 关联 Issue，记录实际验证和未测范围；按项目规则以 `--no-ff` 合入开发分支。
5. 验收通过后关闭 Issue。不要用关闭 Issue 代替未完成的实机验证；延期、受阻或取消应记录原因。

先通过一个小 Issue 落实缺陷/功能/兼容性模板与完成清单。远程不可用时可先保存本地草稿，不编造 Issue 编号，不将本地草稿声称为已发布 Issue。本计划尚未批量创建远程 Issue。

提交公共 Issue 或日志附件时只使用合成输入与脱敏状态，不附用户输入、剪贴板、短信、私人配置或完整设备日志。设备测试继续严格遵守 [测试规则](../AGENTS.md) 与 [保护流程](testing.md)：开始前备份 IPA Board 软件和私有数据，结束后恢复、校验并删除备份，恢复失败则保留恢复入口。

## 2. 尝试适配鸿蒙 4.2.0.x 设备

先确认目标设备的型号、完整 `4.2.0.x` 构建号、APK 安装与 Android 输入法框架支持、实际 API、ABI、页大小，以及是否提供 Google Play 服务。不能把 HarmonyOS 4.2、HarmonyOS NEXT 和 OpenHarmony 当作同一平台，也不能从“4.2”推断 Android API。

目前应用最低 API 35，目标 API 36，编译 SDK 36.1，只打包 ARM64 与 x86_64。低于最低 API 的设备不能仅靠换安装方式获得兼容；若需要降低 `minSdk`，先完成 API、依赖、JNI 动态符号和原生构建要求审计，再确定支持下限。

已知需要审查的调用包括 API 33 的返回回调、API 30 的窗口 Insets 和 `stateDescription`。返回回调需要兼容层，并避免旧系统提前加载缺失类。应用的兼容改造与测试工具的兼容改造分开登记 Issue。

受保护测试还依赖 `run-as`、包状态读取、停止/恢复命令等能力，当前工具要求 `cmd package unstop`。应先验证完整的快照恢复路径；不支持安全恢复时停止设备写入，不能直接安装、卸载、清数据或绕过保护工具继续。

验收至少覆盖安装与升级、启用/切换输入法、窗口尺寸与返回、编辑器输入、三语候选、后台服务恢复、剪贴板和配置持久化。无 Google Play 服务时基础输入仍应可用，SMS Retriever 单独显示不可用或降级。报告限定实际测试型号与构建号；若无法运行，记录具体阻断条件，不将“尝试适配”写成兼容已完成。

官方参考：[华为安装包说明](https://consumer.huawei.com/cn/support/content/zh-cn01089223/)、[Android 最低版本规则](https://developer.android.com/guide/topics/manifest/uses-sdk-element.html)、[返回回调 API](https://developer.android.com/reference/android/window/OnBackInvokedCallback)、[AOSP 包管理命令](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android15-release/services/core/java/com/android/server/pm/PackageManagerShellCommand.java)。目前没有可靠的官方资料证明目标 `4.2.0.x` 构建对应哪个 Android API，必须实机确认。

## 3. 修复偶发无候选问题，完善运行日志管理

优先保留和复现用户观察到的“偶发无候选”，不先假定是词库不足或某个引擎故障。区分正常无匹配、全局禁用、加载中、请求待回复、超时、进程断开、初始化/查询失败和过期结果被拒绝。

当前诊断默认关闭，仅输出固定加载阶段和错误码到 Logcat，不保留应用日志文件。引擎查询尚无明确超时，进程级失败标志也可能保持到进程重建；这些是需要调查的状态路径，不是已经确认的偶发故障根因。

分开推进以下任务：

- 建立覆盖冷启动、后台恢复、快速输入/退格、切页、切换引擎、混输和异步晚到回复的复现用例。
- 为加载、查询与 IPC 定义有界等待和显式状态，保证原文提交及其他可用引擎继续工作。
- 设计有限重试、取消和用户主动重试入口，避免每次按键反复初始化或无限重绑；恢复不能清空用户数据，也不能丢失组合输入。
- 为结果关联输入代次、页策略版本和请求标识，拒绝来自旧页、旧配置或旧进程的回复。
- 建立统一日志管理器：默认关闭，可查看、清空及主动导出；内存缓冲和可选持久化都有容量、保留时间及轮转上限，先明确保留规则再实现。

日志继续采用固定事件和错误码，可记录状态转换、请求标识、耗时和候选数量；不记录输入原文、候选文本、上下文、剪贴板、短信、私人配置/路径或任意异常文本。现有 `Candidate.id` 含候选文本，不可直接作为日志标识。多进程缓冲通过 IPC 汇总，清空动作带版本标识，避免晚到的旧进程事件重新填回日志。应用日志与原生库日志的控制范围应明确，不能声称总开关已经控制第三方库的一切输出。导出通过用户主动选择完成，不自动上传，也不把日志提交到仓库。

验收包括可重复的故障与恢复、正常空候选不误报、超时不阻塞输入、日志开关即时生效、容量/轮转/清理、导出脱敏和记录失败不影响输入。测试以合成数据和离线故障注入为主，真实引擎成功链路单独验证。

## 4. 新增仪表盘功能页

快捷查看输入法服务、各引擎和日志的运行状态，并提供跳转 Keyboard Management 的入口。显示当前页有效策略、引擎未加载/加载中/可用/禁用/故障/超时、最近固定错误阶段及有限重试入口；同时显示日志开关、缓冲/存储使用和清理/导出动作。

仪表盘读取与输入链路共享的状态快照，不自行推断健康状态，也不因打开页面而初始化所有原生引擎。多进程状态带更新时间，断开或过期时显示未知/不可用；“全局开启”不等于“当前页启用”或“已成功加载”。

验收覆盖空闲状态不触发加载、后台进程重建后的状态刷新、错误与恢复显示、日志关闭后的状态、快捷跳转，以及与普通管理入口一致的黑灰样式、字号与可访问性。

## 5. 以键盘页为单位绑定多语言引擎

页面可继承全局设置，或选择允许参与候选的语言/引擎。建议优先采用允许列表，后续是否支持来源优先级另开 Issue，避免初期将开关、权重和模型参数混在一起。

有效策略遵循“全局能力开关 + 页面允许范围 + 输入框安全条件 + 当前功能模式”：页面不能重新开启全局关闭的能力；密码或非文本输入框仍保持直接输入。页组负责页面归属与外观，同一页面在不同组中的引擎绑定保持一致。

先确定稳定页面标识和配置迁移方式，不使用显示名称作为唯一身份。重命名保留绑定，删除清理引用；复制/导入产生明确的新身份。旧页未配置时继承全局，未知或不可用的引擎标识保留兼容信息并采用明确回退。绑定应支持导入/导出，格式升级需兼容旧布局。

切页不丢组合输入，同时使旧策略请求失效，并按新策略重新查询。页面无候选引擎、引擎不可用或未安装时仍能原样提交；E5 只对当前允许的候选排序。策略显式传给隔离进程，不依赖跨进程读取偏好。

验收覆盖继承/覆盖、全局关闭优先、全部关闭、跨组同页、重命名/删除/导入、未知引擎、快速切页和异步晚到回复。页面策略与运行状态要在仪表盘及管理页显示一致。

## 6. 完善计算器功能

先将计算语法、错误状态和结果格式写成行为合同，再逐步扩展。当前仅有基础四则、小数与负数，不支持括号，结果最多四位小数。

建议本版优先支持括号与运算优先级、一元正负号、除零/不完整表达式的明确状态，并改善精度、舍入和结果上屏。当前解析器会跳过未知字符，源码可推导 `2*(3+4)` 被算成 `2*3+4`、`abc1+2` 被算成 `1+2`；这是应优先处理的正确性问题，须严格拒绝不支持的语法或真正实现它，同时保留明确的末尾运算符预览合同。百分号、幂、科学函数及历史记录属于后续选择，分别登记 Issue，不混入首轮解析器修复。

计算模式继续默认关闭；全局计算能力关闭时，工具栏和绑定按键不能越过它。非表达式混输不得被计算器误吞，失败时保留原文与其他语言候选。不要用任意代码执行或脚本求值替代表达式解析。

验收覆盖语法优先级、Unicode 运算符、全半角、除零、长输入、精度与舍入、模式开关、提交失败重试和光标编辑；正常输入不因计算失败而丢失。

## 7. 开放用户编辑多功能栏上的功能键

允许显示/隐藏、排序及选择可用动作，提供恢复默认布局。先明确修改范围仅为输入法多功能栏，候选栏和键盘页按键分别管理；工具栏配置建议独立于页面引擎绑定。

保留默认顺序 `⧉ → ⊞ → 顔 → status → ◩ → ∑`，设计时明确状态区是专用组件；返回键盘、候选展开等必要导航不应因用户隐藏动作而失去入口。是否允许同一动作重复、隐藏状态区或按页覆盖，由对应设计 Issue 决定。

动作使用稳定序列化标识，复用键盘按键与快捷键的动作注册；全局开关、全半角和计算器状态保持一致。窄屏、横屏、较大字号时采用明确的布局/溢出策略，不能挤成无法点击的按钮。

验收覆盖保存重建、默认恢复、旧配置迁移、未知动作、重复动作策略、屏幕尺寸、状态与可访问描述，以及所有面板可返回键盘。配置编辑不得改变实际粘贴文本或隐式启动被禁用的引擎。

## 8. 正式搭载 IPA 键盘与自研基础引擎

提供可直接使用的完整 IPA 预置页，明确辅音、元音、附加符号、重音/声调及组合字符的范围。按真实使用流程安排短按、长按与翻页，避免只提供字符清单。新预置通过正常初始化/导入机制进入页组，更新已有安装不覆盖用户编辑的布局。

先为自研基础引擎定义输入编码、输出类型、字表来源与许可、支持语言、候选/提交合同和性能边界。建议从可离线、确定性验证的码表/前缀查询与原文保底起步，再评估 IPA 转写、组合符号辅助或拼写规则；这些具体能力须在设计 Issue 中决定，不默认等同于通用语言模型。

引擎接入统一的能力声明、页绑定、开关、待发请求取消、晚到结果拒绝、错误回退、状态和日志接口；取消标志不能保证中断正在执行的 JNI 调用。现有查询入口默认识别罗马字，自研 IPA 引擎需明确自己的输入判定与分段规则；引擎身份采用稳定 ID，避免依靠展示用语言标签判断。首版不要求替换 Rime/Mozc/LatinIME；缺少数据、禁用或查询失败时仍能直接输入 IPA。

验收覆盖常用 IPA 与附加符号、组合/代理对/ZWJ 字符、预览和编辑器完整提交、Unicode 归一化规则、退格、候选选择、页绑定、导入旧配置、禁用和故障回退，以及源数据许可。显示或查询可规范化，但不可未经约定改写用户提交的原文。

## 建议增加的修复与工程任务

以下建议来自当前源码检查；与“偶发无候选”的因果关系尚未建立，应各自登记 Issue，不直接当作该故障的解释。

| 建议 | 现状与目的 | 验收方向 |
| --- | --- | --- |
| 优先修复预输入 Unicode 退格 | `CompositionController.backspace()` 用 `dropLast(1)` 删除 UTF-16 单元，Emoji 可能留下孤立代理；直接编辑器删除与此路径不一致。 | 明确按码点还是可见字符删除，覆盖 Emoji、组合重音、ZWJ 和普通文本，不损坏 Unicode。 |
| 统一 Direct / Mixed 的产品合同 | 编辑器与配置仍提供 `textBehavior`，普通文本框短按、长按却统一进入组合输入。 | 决定恢复区别或移除无效选项，兼容旧配置；显示选项必须对应可验证行为。 |
| 修复计算器静默跳过未知字符 | 当前解析器跳过括号、字母等字符，可能将原表达式改写成另一个表达式求值。 | 不支持的语法明确回退，不给出误导结果；保留普通候选和原文。 |
| 设计引擎熔断与安全恢复 | 查询异常可触发进程级失败标志；服务失效、挂起与加载失败需可区分。 | 用确定性故障证明有界等待和有限恢复，保留组合文本，不接受旧回复。 |
| 独立推进 16 KB 原生库兼容 | Mozc 与 ONNX Runtime Extensions 仍为 4KB ELF 对齐；这与最低 API 是两个维度。 | 审查 ELF、APK 打包及运行时页大小假设，并在实际 16KB 环境验证。参考 [官方指南](https://developer.android.com/guide/practices/page-sizes)。 |
| 按职责逐步拆分文件 | IME 服务同时协调输入、面板、工具动作和状态，管理页也承担配置与 UI。 | 按 Issue 将输入会话、引擎策略/状态、日志、仪表盘、工具栏、计算器拆为独立组件；保留行为回归，避免一次大规模搬文件。 |
| 补齐发布与升级验证入口 | 当前自动保护流程验证 debug；签名 release 的真实升级尚未覆盖。 | 先为签名 APK 建立同等软件/私有数据快照与恢复入口，再做旧版升级和配置迁移；不直接安装绕过保护。 |

建议结构先保留现有 `ime/`、`diagnostics/` 等目录，逐步形成引擎协议/状态、输入会话、仪表盘和日志存储的边界。重复功能键通过统一动作注册复用；配置使用版本化迁移，业务状态与 View 分离。目录移动随具体任务进行，不为结构整齐单独制造大规模差异。

## 推进顺序与版本验收

| 阶段 | 建议任务 | 进入下一阶段的条件 |
| --- | --- | --- |
| A：建立闭环 | Issue 模板/完成清单、无候选复现、Unicode 与 Direct/Mixed 合同、鸿蒙只读环境调查 | 复现与状态分类可验证，适配阻断条件有证据。 |
| B：稳定运行 | 有界查询与恢复、统一日志、引擎状态快照、仪表盘 | 状态与日志一致，故障不阻塞基础输入，隐私/容量测试通过。 |
| C：可配置输入 | 页级引擎策略、配置迁移、多功能栏编辑 | 旧布局兼容，切页无过期候选，所有开关优先级明确。 |
| D：输入能力 | 计算器、IPA 预置与自研最小引擎；在前置能力满足后开展鸿蒙受保护实机验证 | 对应 Issue 验收完成，有限功能与未支持范围明确。 |

每个 Issue 先完成主机编译、必要单元/合同测试、lint 与资源校验，再选择相关设备套件；集成和发布前运行完整保护回归。新增设备测试类登记进 `tools/regression-suites.json`，离线与故障回退必须可确定性验证。

发布前明确各 Issue 的完成、延期或受阻状态，更新 README、更新日志、引擎来源和配置格式文档。保留实际设备/API/ABI/编辑器矩阵，不将模拟器、debug 或单台鸿蒙设备的通过结果扩大为全平台兼容。正式发布再设置 `0.0.3` 版本名，并从最终 `main` 发布提交创建 `v0.0.3` 标签；不修改历史 `v0.0.2` 标签。
